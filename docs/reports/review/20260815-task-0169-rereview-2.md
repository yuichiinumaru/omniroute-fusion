## Verification objective audit

### 1. Trust documentation and links — **PASS (20/20)**

`docs/security/PROXY_TRUST.md` documents the no-default-free-list non-goal, staging-only/untrusted scrapers, BYO production path, SSRF defenses, and Hard Rule #20. `AGENTS.md` and `DocumentationTab.tsx` reference it, and the focused tests verify the required content and links.

### 2. Private/loopback/link-local validation — **PASS with persistence residual (21/25)**

The shared literal checker now normalizes whitespace, trailing dots, brackets, case, and host/port forms. Schemas reject literal private/loopback/link-local/metadata hosts, and the named HTTP paths add asynchronous DNS validation. The residual is that database mutation helpers accept a `ProxyPayload` without enforcing the same invariant, so direct/internal persistence can bypass the route-level check.

### 3. DNS rebinding and connectivity probe — **FAIL for full lifecycle enforcement (14/25)**

The reusable guard is technically sound for its exercised surface: it bypasses DNS only for verified public IP literals, resolves hostnames with all answers, rejects any blocked answer, rejects lookup failures/empty responses, and is injectable in tests. The single and bulk promotion routes validate before connectivity testing, and the test suite proves that rebinding rejects without invoking the connectivity tester.

However, the guard is not the canonical invariant at the storage and runtime dispatch boundaries. `promoteFreeProxyToPool()` remains literal-only, and stored proxy data can flow from `resolveProxyForConnection()` into `proxyConfigToUrl()`/`createProxyDispatcher()` without revalidation. That is a material runtime-enforcement gap for pre-existing records, direct helper callers, legacy migration data, and any future caller that bypasses the currently covered routes.

### 4. Free-pool scraper filtering — **PASS (10/10)**

`oneproxy.ts`, `proxifly.ts`, and `iplocate.ts` filter private hosts before staging. The focused provider tests pass.

### 5. Free-pool default posture — **PASS (10/10)**

### 6. Authorization and `LOCAL_ONLY` locality — **PASS (10/10)**

The central route policy includes the free-proxy, registry, proxy configuration, and oneproxy compatibility prefixes. The focused locality matrix covers representative bare and child paths across GET/POST/PUT/PATCH/DELETE. Management authentication remains an additional control, not a substitute for locality.
