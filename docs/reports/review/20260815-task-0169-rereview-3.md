## Runtime call-chain audit

### Stored configured-proxy request path — residual gap

1. `resolveProxyForConnection()` reads a registry or legacy proxy object and returns `{ proxy: { type, host, port, ... } }`.
2. Request/executor callers pass that object to `runWithProxyContext()` or equivalent request context plumbing.
3. `runWithProxyContext()` calls synchronous `proxyConfigToUrl(effectiveProxyConfig)`.
4. `proxyConfigToUrl()` rejects literal private/local hosts, but does not await `assertValidProxyHost()` or any resolver.
5. `isProxyReachable()` performs a TCP reachability check and `patchedFetch()`/`createProxyDispatcher()` constructs the dispatcher. TCP reachability is not a private-address/DNS-rebinding policy check.

The final dispatcher factory is a useful defense against literal URLs, but it is not a substitute for the asynchronous DNS guard for stored hostnames. Dispatcher caching also makes the correct ordering important: validation must happen before cache lookup/construction for a hostname-backed proxy.

### Explicitly guarded egress helpers

`defaultEgressProbe()`, `diagnoseAllEgressIps()`, and `validateProxyPool()` now call `assertValidProxyHost()` before `resolveEgressIp()`/`createProxyDispatcher()` or status mutation. These paths are correctly fail-closed and the new tests prove that their injected rebinding records do not reach the probe seam. This is a real improvement over the 84/100 report, but it covers diagnostics/validation entrypoints rather than every request-dispatch entrypoint.

### Other dispatcher callers

The source audit identified direct calls from `proxyFallback.testSingleProxy`, `patchedFetch` (normal and fallback dispatch), `MimocodeExecutor.getProxyDispatcher`, and the promotion/test route helpers. The route helpers already validate their inputs, while fallback candidates are normally scraped IP literals. The general synchronous factory remains the shared boundary through which a stored hostname can bypass DNS validation.
