## Findings

### High — authoritative anti-downgrade contract remains unimplemented

The implementation's `foreign_toolset: false` metadata is not the reference discriminator. The reference (`legacy/freebuff/common/src/constants/foreign-client-signals.ts:67-72,131-151`) uses the presence of a recognized signature tool, excludes generic names such as `glob`, `web_search`, `write_file`, and downgrades foreign toolsets to `inclusionai/ling-3.0-tiny:free`. A request containing only the tested `calculator`/`test_tool` shape would still be classified as `foreign_toolset` by that detector. The current unit tests verify metadata and schema preservation, not the actual detector semantics.

### High — structured admission 429s are not connected to provider breaker state

The new `ProviderError` carries useful structured fields, but the call graph shows no Freebuff path invoking the existing provider failure/cooldown mechanisms. Thus “triggers circuit breaker” remains a claim rather than verified runtime behavior.

### Medium — strict external response validation remains absent

`requestDeviceCode`, `pollToken`, and `ensureFreebuffSession` decode external JSON and then use broad records/manual field checks. Wrong-typed fields, unexpected statuses, and malformed-but-object responses are not rejected by strict schemas.

### Medium — repository-wide verification remains red and runtime coverage is unit-only

Scoped lint and focused tests pass, but the literal repository lint command remains red because of seven `visual-reference` errors. No mocked route-level OAuth test or production-entrypoint audit packet demonstrates the full sanitized/error/fallback chain.
